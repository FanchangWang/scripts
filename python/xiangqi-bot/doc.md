## 项目需求
使用 Python 编写中国象棋自动脚本。

### 运行环境
```text
Windows 11
Python 3.12
```

### Python 依赖
```text
uv 包管理，创建项目也使用 uv init 等语法进行创建，依赖库等用 uv add 添加。

依赖
pure-python-adb Android adb 库，用于截图以及模拟点击
opencv-python 图片识别
numpy

dev 依赖
ruff 格式化代码
ty 语法检查
```

### UV 添加 Ruff ty 配置

```toml
[tool.ty.environment]
python = ".venv"

[tool.ruff]
target-version = "py312"
line-length = 100

[tool.ruff.lint]
select = [
    "E", "W", "F", # 标准
    "I", # 导入
    "UP", "RUF", # 代码现代化
    "B", "BLE", "T10", # Bug
    "SIM", "C4", "PERF", "PIE", # 简化与性能
    "N", # 命名
    "PTH", # 路径
    # "ASYNC", # 异步（如项目用 asyncio 则保留，否则删掉）
    "PT", # 测试
    "TRY", # 异常
]
ignore = [
    "E501",   # 忽略超长行 (交给 ruff format 自动处理)
    "TRY003", # 允许在 raise Exception(...) 中写长文字说明
    "RUF012", # 允许在类定义中定义可变对象属性 (非常适合 YAML/JSON 配置类)
]

[tool.ruff.format]
indent-style = "space"
quote-style = "double"
docstring-code-format = true
```

### 编程要求
- uv 的配置文件要求用 uv init 等初始化项目的命令自动生成，禁止直接生成 .toml 文件然后再 uv sync 的方式
- 脚本需要的库等依赖必须用 uv add xxx 的方式自动添加到配置文件中，禁止编辑 .toml 添加后再 uv sync 的方式
- 运行脚本的时候 必须使用 uv run 的方式运行，禁止使用 python xxx 方式运行
- 脚本编写完必须使用 uv 运行 ruff 与 ty 检查，经常使用的话可以编写一个 .ps1 脚本，用于检查

### 前置文件
- pikafish\pikafish-bmi2.exe 象棋引擎
- templates/*.png 象棋模板图片
- scripts\visualize_grid.py 验证象棋棋盘棋子中心点的脚本
- scripts\extract_piece_templates.py 切割象棋模板图片用的脚本(内部用了 visualize_grid.py 验证之后的棋盘棋子中心点坐标)

### 象棋语法约定
- 使用 FEN 字符串
- 使用 UCCI / UCI 协议跟 pikafish 进行通信
- 棋盘行列使用 a-i 0-9 的格式记录，比如 h2 表示初始棋局红炮的所在格子

### 脚本 主流程
1. 检查 adb devices 连接设备
    - 无设备连接，脚本提示并结束
    - 一台设备连接，直接使用此设备
    - 多台设备连接，列出并让用户选择使用哪个设备（输入数字或者键盘上下选择设备）
1. 使用 adb 判断手机分辨率是否为 1080*2400，否：脚本结束
1. 询问用户要进行的操作：初始化对局（默认，回车）、q 退出脚本
1. 初始化对局（同时判断自己是红棋还是黑棋）
1. 如果自己是红棋，询问用户要进行的操作：走棋（默认，回车），拉取新棋盘数据（比如自己手动走了棋，等待对方走棋之后，就可以拉取新棋盘数据），初始化对局（比如直接投降，那就等重新开局后进行初始化），q 退出脚本
1. 如果自己的黑棋，询问用户要进行的操作：拉取新棋盘数据（默认，回车。对方红棋先走，所以需要等待对方走棋之后，拉取新棋盘数据），初始化对局，q 退出脚本

#### 子流程 打印当前棋局
1. 使用彩色文字或背景的方式，在终端中模拟打印当前棋盘
1. 棋盘上下标注 a-i  棋盘左右标注 0-9 ，红黑棋子文字使用不同颜色
1. 如果知道哪个棋子的变化路径，比如 h2e2 ，那用颜色标记一下棋子原位置与当前位置
1. 注意有棋子的格子与空格子的文字，宽度要保持一致，便于绘制的棋盘是矩形规整的，不要文字宽度不同导致参差不齐

#### 子流程 初始化对局
1. 如果有历史对局，那清除历史adb截图以及历史保存的自己红黑方
1. 使用 adb 获取截图
1. 使用棋盘棋子坐标以及棋子模板图片分析当前棋盘上的棋子
1. 分析棋子时，检测 "r_K.png" # 红帥 "b_k.png" # 黑将 哪一个在棋盘下方（也就是行数 > 5），那自己就是红棋/黑棋
1. 保存当前截图，用于下一次拉取截图对比棋子位置变化，分析走位棋子
1. 子流程 打印当前棋局

#### 子流程 拉取新棋盘数据
1. 使用 adb 获取截图
1. 检查是否存在历史截图，不存在历史截图时，直接使用 初始化对局 的逻辑，重新分析棋盘布局与红黑方
1. 存在历史截图时，使用棋盘棋子中心点坐标，对比两张截图中心点范围 10x10 的图片是否有差异，如果有差异表示这个位置的棋子发生了变化
1. 如果格子中棋子发生了变化，使用 棋子模板图片 分析当前格子现在存放的哪个棋子或空（无棋子）
1. 子流程 打印当前棋局
1. 整理所有的变化，理论上最低也有2个格子发生变化，因为走一个棋子至少是从 A 格子到了 B 格子。如果中间有自己手动走的情况，那变动的可能更多，比如自己走了一个棋子，对面走了一个棋子，那可能有 4 个格子变化，如果是吃子，也有可能是 3 个格子变化。
1. 如果格子变动比较少，能分析出走位逻辑，比如就2个格子变化，A格子从黑炮变成空，B格子从空变成黑炮，那就说明黑方移动了炮这个棋子，可以用日志打印出来。如果格子变动很多，不好分析棋子的变动，那日志就只列出 A 黑炮->空  B 空->黑炮 这样的简单日志，能看出来是哪些格子发生了变化。格子使用 a2 b3 这种方式进行标记。

#### 子流程 走棋
1. 调用 pikafish 计算出下一步要走的棋
1. 使用 棋盘棋子中心点坐标 获取原位置坐标，以及要去的位置的坐标
1. 打印日志（包含要走的棋子、原位置与屏幕坐标、新位置与屏幕坐标）
1. 使用 adb 先点击原位置坐标提起棋子，间隔 500 毫秒，点击要去位置的坐标放下棋子
1. 延时 800 毫秒，使用 adb 重新截图
1. 校验棋子是否走动成功：使用 棋子模板图片，分析原位置是否不等于原棋子，分析目标位置是否等于原棋子
1. 走动成功：流程结束
1. 走动识别：询问用户操作：重新走棋（默认，回车），拉取新棋盘数据（比如手动把棋走了），初始化对局，q 退出脚本
