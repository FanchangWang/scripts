② Kind 分类重构映射表

现状 kind问题重构后使用场景
INFO 一锅烩：调试细节 + 流程事件 + 交互动作 拆成三类 DEBUG：FEN / 点击坐标 / 布局识别 / VirtualDisplay 参数
INFO：流程事件（开始棋局、等待对方走棋、自动下一局已开启）
—— 交互动作归 INFO + [交互] tag
OK 既当「初始化成功」又当「局面信息」 OK 只保留「里程碑成功」：引擎就绪、OpenCV 初始化、我方识别成功、授权成功；局面信息（「残局模式：轮到红方」）改 INFO
MOVE 语义漂移：引擎着法用 INFO，结算按钮点击反而用 MOVE MOVE 我方着法专用：中文记谱 + 评估分（「炮二平五（评估 +36）」）；结算按钮点击改 INFO+交互 tag
ENEMY 只有 4 字「炮8平5」，无上下文 ENEMY 对方着法专用：中文记谱，tag 补上下文
GAMEOVER 与 INFO 的「[结束触发点]」重复打两遍 GAME 对局节点专用：结束原因、下一局开始；合并「触发点」内部日志为 DEBUG
WARN / ERROR 基本合理 不变 维持现状
（无） 模块来源不可知，手工 [校准] 前缀不统一 新增 tag 字段 [系统] [服务] [引擎] [视觉] [校准] [对局] [我方] [对方] [交互] [下一局] —— LogEvent 结构化字段，替代字符串前缀
